# UPD-07 updater tests fail at random on the Mac

## Request
On the Mac, `scripts/features/precheck.sh` failed in the worker stage. Each run failed different tests in `test_self_updater_timeout.py` and `test_self_updater_hardening.py`. First the pip timeout test, then the coordinator added more: the lock tests, `haengendes_git_show`, `haengender_diff` and others. Each test passed when it ran alone. Make the worker stage pass reliably. Do not skip, do not use `xfail`, do not increase a limit, do not change the production code.

## Cause
All failing tests use the fixture `vps`. The fixture writes a new shell script `git` into `tmp_path/bin` and puts it first in `PATH`. Every git call of the updater goes through this script. The pip test also writes a new script as a fake Python.

macOS examines a new executable file when it starts for the first time. We measured a fresh copy of the script in the fixture of 81 tests (load 3–25):

| Start | Median | Max | Over 1 s | Over 3 s |
|---|---|---|---|---|
| First start | 0.56 s | 3.58 s | 32 of 81 | 5 of 81 |
| Second start | – | 0.10 s | 0 | 0 |

The git limits in the fixture are 3 s, the pip limit is 1 s. In the same runs, 4 tests failed. Each failure was a timeout of the **first** git call of the flow (`git rev-parse` twice, `git stash`, `git fetch`), not of the command that the test makes hang. Example: `haengendes_git_show` expects a timeout of `git show`, but got `git fetch: 3 sn içinde bitmedi`. The pip test failed with `FileNotFoundError: grandchild.pid`, because the script stopped before it wrote the file.

We also measured the real git calls after the warm-up (2 rounds, load 10–78): 286 calls, median 0.03 s, p95 0.29 s, max 1.32 s. Thus the 3 s limit has enough margin. A clock jump after sleep was not seen in these runs.

## Solution
| File | Change |
|---|---|
| `worker_python/tests/unit/test_self_updater_timeout.py` | New helper `warm_up(script, *args, env=None)`. The fixture `vps` starts the fake `git` once with `--version` (it runs the real git) before a limit starts. |
| `worker_python/tests/unit/test_self_updater_hardening.py` | The fake Python stops at once with `--warmup`. The pip test calls `warm_up(fake_python, "--warmup")` before the 1 s limit. |

## Why
- The warm-up removes only the first-start check of macOS. The limits (1 s, 3 s), the commands and all assertions stay the same.
- Rejected: larger limits (forbidden, and the tests become slower). Rejected: wait for the PID file after the call (when the script stops before it writes the file, there is no grandchild to check). Rejected: limits calculated from a measured delay (more code, and the first-start delay is not stable).

## Verification
- Before the fix: 4 failed in 3 rounds of both files (81 tests). The pip test alone: 2 of 4 failed.
- After the fix: both files 5 rounds in sequence, 135 of 135 passed (load 12–28). 2 more rounds with timing: 54 of 54 passed (load 10–78). The pip test alone: 12 of 12 passed.
- Mutations of `src/utils/self_updater.py` (each reverted with `git checkout`):

| Mutation | Tests | Result |
|---|---|---|
| A: limit + 30 s in `_run_limited` | pip, `haengendes_git_show`, `haengender_diff` | all 3 failed (`assert True is False`) |
| B: on timeout stop only the direct process | pip | failed (duration 23 s > 15 s) |
| C: `_lock_is_stale` ignores a dead PID | `lock_eines_beendeten_prozesses` | failed |
| D: `_lock_is_stale` ignores the age | `sehr_alter_lock` | failed |
| E: `_remove_stale_ref_locks` keeps all locks | `veralteter_ref_lock_nach_kill` | failed |

- `scripts/features/precheck.sh`: result in the PR description.

## Lessons
- On macOS, a test that writes a new executable file and starts it under a short limit must start it once before the limit. Use `warm_up()` from `test_self_updater_timeout.py`.
- Other tests with short limits (`test_ws_stream.py` 0.1 s, `test_market_api.py` 0.2 s) do not start new files. They did not fail in these runs.
