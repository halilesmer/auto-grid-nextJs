# Backtest: zone start from telemetry z0 (BKT-31, PR-3)

## Request

Plan 1114-M1 §4.1 and §4.2. The worker writes `z0` for each full turn (time from turn start to the start of the zone loop, ENG-35). The backtest must use it for the zone start of setup m.

## Solution

- `turnSchedule.ts`, source `telemetry`, turn with `z0`: `zoneAt = start + z0 + Σ over lower zones (op cost of that zone in this turn + profile.vps.zoneOverheadS)`. `z0` already contains the read time and the SLTP changes at the head, so the old `head + sltp` terms are not added.
- A turn without `z0` (old row, or null) keeps the old formula `start + pre + headS + sltp + Σ lower op costs`. The source `liveOrders` never has `z0` and stays byte-identical.
- Constraint (plan §3.3 item 5): `zoneAt < snapAt` becomes `snapAt`. The schedule counts these cases in `zoneBeforeSnap`. `z0Turns` counts the turns that use the new path.
- `run.botTurns` gets `zoneFromZ0Turns` and `zoneBeforeSnap` only when at least one turn used `z0`. Other runs keep the same log.
- `calibrationDerive.ts` (PR-4) already derives `zoneOverheadS` (quiet turns with `z0`: `(dur − z0)/setups`) and `opCost.sltp` (slope of `z0 − snap` against `nsl0`) from the calibration window. It needed no change. Both stay at the default value when the window has too few turns with `z0` or `nsl0`.
- The default profile has `zoneOverheadS = 0`. Without a derived profile the new path is `start + z0 + Σ lower op costs`.

## Tests

`e2e/mocked/backtest-zone-z0-lib.spec.ts` (`@BKT-31`): old row keeps the old formula, `z0` plus lower op costs, overhead per lower zone without an op, mixed turns, clamp to `snapAt` with counter, `liveOrders` unchanged.
